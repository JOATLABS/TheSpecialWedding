2. Retention Strategy

Meeting all four standards with a tiered approach.

D1 — Hot (0-3 mo)Instant queries, dashboards
D1 — Warm (3 mo – 2 yr)Queryable, SOC 2 / PCI audit window
R2 — Cold Archive (2 – 5 yr)GDPR complaints, legal disputes

PCI DSS 4.0

12 months available, 3 months instant. ✅ D1 hot tier covers this fully.

SOC 2 Type II

12 months continuous monitoring evidence. ✅ D1 warm tier provides full year.

GDPR

3+ year complaint window. ✅ R2 cold archive covers dispute lifecycle.

4. Event Emission Flow

1
HTTP Request arrives at FastAPI

Existing AuditLoggingMiddleware captures request metadata (IP, user-agent, auth token, path, method)

2
AuditEmitter enriches and forwards

New middleware layer wraps existing audit middleware. After response, constructs a compliance-grade event with before/after snapshots, data classification, and consent basis. Sends async POST to Cloudflare Audit Ingestion Worker.

3
Service-level audit calls (enriched events)

Critical services (stripe_service, contract_service, auth_service, couple_portal_service, vendor_service) emit domain-specific events with before/after snapshots directly via the AuditEmitter client. These contain richer context than middleware can capture.

4
Ingestion Worker validates and stores

Worker validates event schema, computes hash_chain (tamper evidence), classifies data, writes to D1. Returns 202 Accepted. If D1 write fails, buffers to KV for retry.

5
Weekly archival cron

Cron Worker selects records older than 2 years, gzips as monthly JSON partitions, writes to R2 bucket, deletes from D1. Also IP-hashes records older than 90 days (GDPR IP minimization).

6
Query Worker serves dashboard

Read-only Worker API serves filtered queries for admin dashboard. Supports: date range, actor, event type, resource, wedding, data classification. Returns paginated results.

GDPRSELF-AUDIT
Weekly cron Worker. Selects D1 records > 2 years old, compresses to gzipped JSON partitioned by month (e.g., archive/2024/03.json.gz), writes to R2, deletes from D1. Also runs IP anonymization on records > 90 days (GDPR data minimization).

6. Migration Strategy — What Stays, What Changes

The existing audit system continues to work. The new compliance layer runs in parallel.

Stays Unchanged

MongoDB audit_logs — Short-term operational logging (30-day TTL). Powers existing admin activity feed. Low-cost, high-volume.

MongoDB security_audit_logs — Security event detection with 180-day TTL. Powers suspicious activity detection. Stays for real-time alerting.

MongoDB activity_logs — Planner dashboard activity feed. User-facing, not compliance-related.

AuditLoggingMiddleware — Continues as-is. New compliance middleware runs after it.

New Compliance Layer

Cloudflare D1 — Long-term compliance store (2 years active). Physically separated from app data for tamper resistance. Hash-chained for integrity proof.

Cloudflare R2 — Cold archive (2-5 years). Compressed, partitioned by month. Retrievable for legal/audit requests.

ComplianceAuditMiddleware — Enriches events with GDPR/PCI/SOC 2 fields. Runs alongside existing middleware.

Admin Audit Dashboard — Queries D1 via Audit Query Worker. Full filtering, export, compliance views.
