## Subscription guardrails — soft-cap AI credits, hard-cap storage, lifecycle bug fixes

Replaces the counter-drift–prone subscription cap surface with live-query checks against source-of-truth collections, adds a metered-overage path for AI credits, and closes three production bugs the integration run surfaced in the same area.

### Cap-check rewrite (`subscription_service.py`)

- **`ai_credits`** — soft cap with metered overage. Live-query aggregates `credits_used` from `ai_usage_log` per calendar month. Returns `allowed=true` always; annotates `overage`, `overage_credits`, `overage_credits_projected`, `overage_price_per_credit_usd`, `overage_cost_cents` for the UI and billing to pick up at period close.
- **`storage`** — hard cap. Live-query against `guest_media_assets.size_bytes`. Returns `current_usage_bytes`, `current_usage_gb`, `limit_gb`. `-1` limit = unlimited (Agency tier).
- **`staff_seats`** — hard cap. Live-query against `team_members{owner_id, status}`.
- **`weddings`** — already live-queried; **fixed** to exclude soft-deleted weddings (`deleted_at` set/None filter). Previously a planner who archived a wedding still had that slot consumed.

### Webhook sync gaps (`stripe_service.py`)

- **Plan-snapshot grandfather rule** now distinguishes admin-edited plan limits (snapshot preserved) from user-initiated plan changes (snapshot refreshes). Previously a Boutique→Signature upgrade left `plan_snapshot.max_weddings=3` forever — weddings #4–10 were silently capped.
- **Cancellation state sync** — added `cancel_at_period_end`, `canceled_at`, `cancel_at` to `subscription_updates`. Stripe knew the sub was set to cancel; Mongo never learned. Cancellation banner stayed hidden, renewal cron couldn't skip about-to-die subs.
