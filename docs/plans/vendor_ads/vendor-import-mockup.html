Design Notes

Service Manager Changes (options 11–14)

  • Option 11 — Run scraper: Opens a new tmux pane, prompts for cities and categories interactively, then runs python -m app.jobs.vendor_scraper.run with the selected args. Logs stream in the pane — you watch them live.
  • Option 12 — Dry run: Same as 11 but auto-appends --dry-run. No DB writes, just logs what would happen.
  • Option 13 — View scraper logs: Switches to the scraper tmux pane (or tails .service-manager/logs/scraper.log if no pane is active).
  • Option 14 — Export to JSON: Queries vendor_profiles for records from the last scraper run (using created_by: system@thespecialwedding.com + timestamp window), dumps to a JSON file in .service-manager/exports/. This is the file you drag into the admin import modal.

Admin Import Modal

  • Trigger: "Import Vendors" button on the existing vendor management page. ROOT_ADMIN only — button hidden for other roles.
  • File validation: Accepts .json only. Client-side schema check before showing preview (must match vendor scraper export format).
  • Preview: Parses the JSON, diffs against existing vendor_profiles by google_place_id, shows new vs. update counts. Scrollable vendor list.
  • Import endpoint: POST /admin/vendors/import — accepts the JSON array, runs vendor_service.upsert_scraped_vendor() for each entry. Returns success/error counts.
  • Sanitization: All scraped text fields (name, description, website content) are sanitized server-side before DB write — strips HTML, validates URLs, enforces max lengths.
  • No SSE needed: Import of ~50–200 records completes in seconds. Simple loading spinner → success toast.

Architecture Summary

  • Scraper runs locally via service manager → outputs to DB directly (existing behavior) or exports JSON
  • Import modal is a thin frontend → hits one new API endpoint → reuses existing VendorService.upsert_scraped_vendor()
  • Zero new infrastructure: No SSE, no background tasks, no new scheduler, no API key on server
  • Security surface: Minimal — just one new authenticated ROOT_ADMIN endpoint that accepts pre-validated data
