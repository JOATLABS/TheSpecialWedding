# Vendor Advertising Monetization Platform - Admin Runbook

## Platform Overview

The Vendor Advertising Monetization Platform enables vendors to reach planners through sponsored ads integrated into "The Special Wedding" planning app.

**Architecture:**
- Campaign-centric design with `ad_campaigns` and `ad_creatives` collections
- Campaigns group multiple creative assets (headlines, descriptions, offers, images)

**Three Portals:**
- Admin Console (`/admin/ads/`) — root admin control
- Vendor Portal (`/portal/ads/`) — vendor self-service campaign management
- Planner Experience (`CampaignSponsoredRail`) — integrated on 4 planner pages

**Business Model:**
- Free tier: $0 billing
- Metrics tracked: impressions, clicks, leads, engagement rates
- Revenue calculations placeholder for future paid tiers

## Daily Operations

### Reviewing Campaigns (Creative Review Tab)

The review queue surfaces campaigns pending approval before they serve ads to planners.

**Process:**
1. Open the Creative Review tab
2. Review queue displays campaigns with status `pending_review`
3. Review counts bar shows: pending / approved / rejected totals

**Per Campaign Review:**
- Headline and description (brand alignment, clarity)
- Offer details (value proposition, clarity)
- Call-to-action text (compelling, appropriate)
- Creative image (brand quality, relevance)

**Actions:**
| Action | Result | Next Step |
|--------|--------|-----------|
| **Approve** | Status → `active` | Campaign begins serving immediately |
| **Reject** | Status → `rejected` | Vendor must resubmit from scratch |
| **Request Changes** | Status → `draft` + feedback | Vendor revises and resubmits for review |

**Creative Asset Review:**
- Separate review queue for individual creative assets within campaigns
- Follow same approval workflow

**Approval SLA Target:** 24–48 hours from submission

### Monitoring Active Campaigns (Campaign Monitor Tab)

Monitor all active campaigns and take enforcement actions.

**Campaign Table:**
- Filter by status, vendor
- View all campaigns across vendors
- Real-time campaign metrics

**Admin Actions:**
| Action | Effect | Use Case |
|--------|--------|----------|
| **Pause** | Temporarily stops serving; status remains `active` | Suspicious activity, policy violation, vendor request |
| **Deactivate** | Permanently kills campaign; status → `deactivated` | Fraud confirmed, vendor account suspended |

**When to Pause:**
- Unusual click patterns detected
- Policy compliance concerns
- Vendor requests pause for any reason
- Vendor dispute or fraud investigation underway

**When to Deactivate:**
- Fraud definitively confirmed
- Vendor account suspended or terminated
- Unrecoverable policy violation

### Revenue Dashboard (Revenue Tab)

Current platform metrics and vendor performance.

**Display:**
- Current tier: Free (shows $0 revenue)
- Key metrics:
  - Total impressions (all campaigns)
  - Total clicks (all campaigns)
  - Total leads (all campaigns)
  - Platform CTR (clicks / impressions)
  - Conversion rate (leads / clicks)

**Vendor Leaderboard:**
- Top vendors ranked by engagement
- Benchmark performance across vendors

**Period Filtering:**
- Daily, weekly, monthly views
- Use to identify trends and seasonal patterns

### Vendor Accounts (Vendors Tab)

Manage all vendor advertiser accounts.

**Vendor List:**
- Account summaries per vendor
- Campaign count (campaigns created)
- Total spend ($0 for free tier; prepared for future paid tiers)
- Lead count (leads generated by vendor campaigns)
- Status (active, suspended, etc.)

**Admin Actions:**
- **"Log in as vendor"** — Opens vendor portal with admin privileges; useful for debugging or testing vendor workflows
- **"Create Vendor"** — Shortcut in sidebar to create new vendor accounts

### Planner Feedback (Feedback Tab)

Monitor planner reactions to campaigns and manage auto-pause triggers.

**Metrics:**
- Hide rate per campaign and vendor
- Category suppression patterns (planners hiding specific vendor categories)
- Campaign pause trigger alerts

**Auto-Pause Rules:**
- If 3+ unique planners hide the same campaign → campaign auto-pauses
- Alert surfaces in this tab

**Use for:**
- Guiding creative review decisions (campaigns with high hide rates may warrant scrutiny)
- Identifying vendor quality issues
- Detecting policy violations via planner feedback

## Vendor Management

### Creating a Vendor Account (Free Tier Shortcut)

Add new vendors to the platform.

**Steps:**
1. Open Vendor Accounts tab
2. Click "Create Vendor" in sidebar or "Vendor Portal" link
3. Fill in:
   - Vendor email address
   - Assign temporary password
4. Send vendor their credentials via email
5. Vendor logs in to `/portal/ads/` and creates first campaign

### Reviewing as Vendor

Debug vendor workflows or test features by impersonating a vendor.

**Steps:**
1. Open Vendors tab
2. Click "Log in as vendor" on target vendor row
3. Vendor portal opens with admin indicator in sidebar
4. Admin can:
   - Create campaigns and creatives
   - Test campaign submission flow
   - Verify portal functionality
5. Click "← Back to Admin" link to return to admin console

## System Configuration

### Config Tab Settings

Control platform behavior via feature flags and limits.

**Available Settings:**
- **Feature Flags:**
  - `VENDOR_ADVERTISING_ENABLED` — enable/disable ad serving
- **Serving Limits:**
  - Max cards per rail (sponsored ads per planner page)
  - Frequency cap (impressions per planner per time period)
- **Fraud Thresholds:**
  - Click velocity limits
  - Impression anomaly detection thresholds
- **Data Pipeline Controls:**
  - Nightly rollup triggers
  - Metric aggregation settings

### Nightly Rollup

Automatic daily metric aggregation runs via cron.

**Scheduling:**
- Runs automatically at 2 AM UTC
- Triggered by main.py startup cron
- No manual intervention required

**Computations:**
- `campaign_day_stats` — per-campaign daily metrics (impressions, clicks, leads)
- `placement_day_stats` — per-placement daily metrics

**Verification:**
- Check `campaign_day_stats` MongoDB collection for completed rollup
- Review admin console Revenue Dashboard for updated metrics

**Troubleshooting Nightly Rollup:**
See [Troubleshooting](#troubleshooting) section below.

## Fraud Monitoring

### Fraud Signals Dashboard

Monitor suspicious activity and take enforcement action.

**Signals Tracked:**
- Click velocity anomalies (abnormal click patterns)
- Impression anomalies (unusual serving patterns)

**Current Implementation:**
- CRUD-only: manually create, update, dismiss, and delete signals
- Detection logic deferred to future phase

**Actions on Signals:**
| Action | Effect |
|--------|--------|
| **Acknowledge** | Log signal as reviewed; no auto-action |
| **Dismiss** | Close signal without action |
| **Escalate** | Flag for deeper investigation; creates incident |

**Future Enhancements:**
- Automated click velocity detection
- Pattern analysis and anomaly scoring
- Auto-pause on high-severity signals

## Troubleshooting

### Campaign not appearing in planner rail

Debug why a campaign isn't showing to planners.

**Checklist:**
1. ✓ Campaign status is `active` (not `draft`, `pending_review`, or `paused`)
2. ✓ At least one creative has `review_status: approved`
3. ✓ Campaign date range includes today (start_date ≤ today ≤ end_date)
4. ✓ Targeting rules match planner context (categories, regions, demographics)
5. ✓ Frequency capping hasn't been hit (future feature; not yet active)

**Resolution:**
- If status is `draft` or `pending_review`, submit for review and wait for approval
- If creatives are unapproved, review and approve them in Creative Review tab
- Check campaign date range and extend if needed
- Verify targeting configuration matches planner segment

### Vendor can't log in

Resolve vendor authentication issues.

**Steps:**
1. Verify vendor account exists in Vendors tab
2. If account missing, create new vendor account (see [Creating a Vendor Account](#creating-a-vendor-account-free-tier-shortcut))
3. Reset password via admin console and email new credentials to vendor
4. Check if vendor account is suspended; unsuspend if appropriate
5. Verify `/portal/ads/` is accessible (check server health)

### Nightly rollup not running

Fix missing or delayed metric aggregation.

**Steps:**
1. Check server logs for "Nightly campaign rollup" entries and errors
2. Verify main.py startup cron is active and running
3. Check MongoDB connectivity (test DB connection in server logs)
4. If cron is down, restart application server:
   ```bash
   systemctl restart wedding-app
   ```
5. **Manual Rollup:** If urgent, trigger manually from Python shell:
   ```python
   from services.campaign_rollup import CampaignRollupService
   CampaignRollupService.compute_daily_rollup()
   ```
6. Verify results in `campaign_day_stats` collection and Revenue Dashboard
