⚠
Critical Performance Gap: All 5 advertising collections (sponsored_vendors, ad_events, ad_leads, ad_feature_flags, planner_ad_preferences) currently have ZERO indexes. Every analytics query performs a full collection scan. This will degrade significantly as data grows beyond a few thousand documents.
💡
Optimization Strategy (3 Pillars): (1) Compound indexes aligned to exact dashboard query patterns, (2) Pre-aggregated daily rollups via new ad_stats_daily collection to avoid real-time aggregation, (3) TTL retention policies to auto-prune raw events and keep storage lean.

🔍
Index Design Principle: Every compound index below is derived from an actual query pattern in advertising_service.py or the dashboard mockup. Indexes follow MongoDB's ESR rule: Equality fields first, Sort fields next, Range fields last.
ad_events — 5 Indexes Highest Priority

COMPOUND idx_ad_events_vendor_date

CREATE INDEX (sponsored_vendor_id ASC, created_at DESC)
Powers: get_ad_stats() — count recent events for a specific sponsored vendor within a date range. This is the #1 most frequent analytics query.

COMPOUND idx_ad_events_type_date

CREATE INDEX (event_type ASC, created_at DESC)
Powers: Dashboard Overview — count events by type within date range (impressions trend, click trend, conversion funnel).

COMPOUND idx_ad_events_vendor_type_date

CREATE INDEX (sponsored_vendor_id ASC, event_type ASC, created_at DESC)
Powers: Vendor Performance tab — per-vendor breakdown of impressions vs clicks vs leads over time. Three-field compound for covered queries.

COMPOUND idx_ad_events_placement_date

CREATE INDEX (placement ASC, created_at DESC)
Powers: Placement analysis — compare performance across vendor_rail, directory_boost, milestone_module, vendor_detail.

TTL idx_ad_events_ttl

CREATE INDEX (created_at ASC) TTL = 90 days
Auto-prune raw events older than 90 days. Aggregated data preserved in ad_stats_daily. Also serves as the descending sort index (MongoDB reverse scan).
ad_leads — 4 Indexes Lead Funnel

COMPOUND idx_ad_leads_status_date

CREATE INDEX (status ASC, created_at DESC)
Powers: Lead Funnel tab — count leads by status (pending/contacted/responded/converted/closed) within date range.

COMPOUND idx_ad_leads_vendor_date

CREATE INDEX (vendor_profile_id ASC, created_at DESC)
Powers: Vendor-specific lead list, sorted by most recent. Also used by get_leads(filters={"vendor_profile_id": ...}).

COMPOUND idx_ad_leads_type_status_date

CREATE INDEX (lead_type ASC, status ASC, created_at DESC)
Powers: Lead funnel stacked bar chart — leads by type and status over time. Three-field compound covers the full query.

COMPOUND idx_ad_leads_planner_date

CREATE INDEX (planner_id ASC, created_at DESC)
Powers: Per-planner lead history. Used by planner-facing "my leads" view.
sponsored_vendors — 3 Indexes Serving

COMPOUND idx_sponsored_active_placement

CREATE INDEX (is_active ASC, placement ASC, priority DESC)
Powers: get_sponsored_vendors() — the primary ad-serving query. Covers the equality filter (is_active=True, placement=X) and the sort (priority DESC).

COMPOUND idx_sponsored_vendor_profile

CREATE INDEX (vendor_profile_id ASC, is_active ASC)
Powers: Lookup sponsored entries by vendor. Used for vendor performance dashboard and deduplication checks.

COMPOUND idx_sponsored_created_date

CREATE INDEX (created_at DESC)
Powers: Admin listing of sponsored vendors sorted by creation date (recent first). Low cardinality, simple index.
planner_ad_preferences — 1 Index Lookup

UNIQUE idx_planner_prefs_planner_id

CREATE INDEX (planner_id ASC) UNIQUE
Powers: get_planner_preferences(), hide_vendor(), unhide_vendor(), toggle_reduced_frequency() — all lookup by planner_id. Enforces one-preference-per-planner uniqueness.
ad_feature_flags — 1 Index Singleton

UNIQUE idx_feature_flags_key

CREATE INDEX (feature_key ASC) UNIQUE
Powers: get_feature_flag() — singleton lookup. Prevents duplicate flags.
ad_stats_daily — 4 Indexes Rollup Queries

UNIQUE+COMPOUND idx_stats_daily_unique

CREATE INDEX (date ASC, sponsored_vendor_id ASC, placement ASC) UNIQUE
Enforces one rollup per vendor per placement per day. Also serves as the primary query index. Enables upsert-based rollup computation.

COMPOUND idx_stats_daily_vendor_date

CREATE INDEX (sponsored_vendor_id ASC, date DESC)
Powers: Vendor Performance tab — fetch recent daily stats for a specific vendor, sorted by date.

COMPOUND idx_stats_daily_date

CREATE INDEX (date DESC)
Powers: Overview tab — fetch all vendor stats for a date range (last 7/14/30/90 days). Fast date-descending scan.

COMPOUND idx_stats_daily_placement_date

CREATE INDEX (placement ASC, date DESC)
Powers: Placement comparison analytics — compare vendor_rail vs milestone_module performance over time.

Nightly Rollup Aggregation Pipeline
1

$match — Filter yesterday's events

Only process events from the previous day (UTC boundaries)

$match: { created_at: { $gte: ISODate("2026-03-14T00:00:00Z"), $lt: ISODate("2026-03-15T00:00:00Z") } }
2

$group — Aggregate by vendor + placement + day

Count each event type, compute unique planners/weddings, build hourly click distribution

$group: { _id: { vendor: "$sponsored_vendor_id", placement: "$placement", date: { $dateTrunc: { date: "$created_at", unit: "day" } } }, impressions: { $sum: { $cond: [{ $in: ["$event_type", ["impression_served", "impression_viewable"]] }, 1, 0] } }, clicks: { $sum: { $cond: [{ $eq: ["$event_type", "click"] }, 1, 0] } }, leads: { $sum: { $cond: [{ $eq: ["$event_type", "lead_created"] }, 1, 0] } }, unique_planners: { $addToSet: "$planner_id" }, unique_weddings: { $addToSet: "$wedding_id" } }
3

$project — Shape the rollup document

Compute CTR, convert unique sets to counts, format for storage

$project: { date: "$_id.date", sponsored_vendor_id: "$_id.vendor", placement: "$_id.placement", counts: { impression_served: "$impressions", click: "$clicks", lead_created: "$leads" }, unique_planners: { $size: "$unique_planners" }, unique_weddings: { $size: "$unique_weddings" }, ctr: { $cond: [{ $gt: ["$impressions", 0] }, { $multiply: [{ $divide: ["$clicks", "$impressions"] }, 100] }, 0] } }
4

$merge — Upsert into ad_stats_daily

Idempotent: re-running the pipeline for the same day overwrites (not duplicates). Uses the unique compound index.

$merge: { into: "ad_stats_daily", on: ["date", "sponsored_vendor_id", "placement"], whenMatched: "replace", whenNotMatched: "insert" }

🎯
Monetization Path: With pre-aggregated daily stats, you can track the 4 Monetization Readiness thresholds (weekly active planners, avg leads/vendor/week, lead-to-conversion rate, active sponsored vendors) in real-time. When all 4 thresholds are met, you'll have the data confidence to introduce pricing tiers.
