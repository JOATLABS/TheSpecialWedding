🔴 Critical Issues & Recommendations

Issue 1: Badge Component Non-Compliance

Severity: CRITICAL

The Badge component uses generic Tailwind colors instead of the wedding palette. This breaks brand consistency in any status indicators or labels.

Current Code:

default: 'bg-blue-100 text-blue-800'
warning: 'bg-yellow-100 text-yellow-800'
success: 'bg-green-100 text-green-800'

Recommendation:

default: 'bg-wedding-rose/20 text-wedding-rose border-wedding-rose/30'
warning: 'bg-wedding-gold/20 text-wedding-gold border-wedding-gold/30'
success: 'bg-emerald-400/20 text-emerald-100 border-emerald-400/30'

Impact: Any page using Badge component will show brand-inconsistent colors.

Issue 2: Button Component Generic Variants

Severity: HIGH

The Button 'default' variant uses bg-blue-600 instead of brand colors. The outline variant uses generic gray borders.

Current Code:

case 'default':
  variantStyle = 'bg-blue-600 text-white hover:bg-blue-700'

case 'outline':
  variantStyle = 'border border-gray-300 dark:border-slate-600 bg-transparent'

Recommendation:

case 'default':
  variantStyle = 'bg-wedding-rose text-white hover:bg-wedding-blush'

case 'outline':
  variantStyle = 'border border-wedding-rose/30 hover:border-wedding-rose'

Impact: Any secondary buttons using 'default' variant will appear off-brand.

Issue 3: Typography Hierarchy Inconsistency

Severity: MEDIUM

H1 and H2 tags use inconsistent font-weight values (font-semibold vs font-bold) across pages. This reduces visual hierarchy clarity.

Recommendation: Standardize on font-bold (700) for h1 and font-semibold (600) for h2-h3 across all pages.

Issue 4: CSS Variable Misalignment

Severity: MEDIUM

The global CSS custom properties don't match actual usage in pages. --theme-primary is #1e3a5f but pages use #0b1120 or #1D3557.

Impact: Creates confusion for developers and reduces maintainability. CSS variables should be source of truth.

Recommendation: Update globals.css to define actual colors used, or refactor pages to use CSS variables consistently.
