Executive Summary

Overall Assessment

The Special Wedding maintains a strong, consistent brand voice across the frontend. The tone is professional, confident, and elegant—appropriate for premium SaaS targeting professional wedding planners. The dark UI + rose/gold palette reinforces premium positioning effectively.

Key Strengths:

  • Hero copy clearly leads with differentiators (AI, Couple Portal, SMS reminders)
  • Comparison table now uses three-state logic (✓/~/—) with audit qualifiers
  • Feature naming is standardized across pages (18 tools consistently referenced)
  • Testimonials have real names, companies, and specific use cases
  • CTAs show appropriate variation (not all "Start your free trial")

Areas for Attention:

  • Metrics ("99.9% Uptime", "48k+ Guests") lack visible qualifiers or disclaimers
  • Competitor pricing data needs fresh verification (April 2026 claimed, but should verify against live sources)
  • Some hero copy lists features equally; could better emphasize core moat (Couple Portal priority)

Legal & Compliance Flags

High-Priority Issues

Unqualified Metrics: "99.9% Uptime" & "48k+ Guests"
Issue: These claims lack visible disclaimers or context. "99.9% Uptime" implies an SLA without defining scope (does it include scheduled maintenance? customer infrastructure?). "48k+ Guests" lacks attribution (over what time period? by which user cohort?).
Current Metrics (app/page.tsx lines 53-59) const metrics = [ { value: "48k+", label: "Guests managed" }, { value: "5 days", label: "Avg. RSVP turnaround" }, { value: "18", label: "Tools in one platform" }, { value: "99.9%", label: "Uptime" }, ];
Recommendation Add visible qualifiers: Either (1) add a footnote below metrics, (2) change labels to include qualifier, or (3) link to SLA/terms. Examples:
- "48k+ Guests*" + small footnote: "*managed by professional planners using The Special Wedding"
- "99.9% Uptime*" + footnote: "*SLA terms and exclusions apply. See SLA."
- Change "5 days" to "5 days average" (already clear, no change needed)
Competitor Pricing Claims May Be Stale
Issue: The comparison table shows HoneyBook at $29/mo, but the audit report flagged that HoneyBook is now $32.50/mo. The page claims "as of April 2026" but should verify live before next deployment.
Current Implementation (features/page.tsx lines 181-184) <td className="text-center px-4 py-4 text-sm font-semibold text-wedding-rose">$29/mo</td> <td className="text-center px-4 py-4 text-sm text-slate-400">$29/mo</td> {/* HoneyBook */}
Recommendation Action Items:
1. Verify competitor pricing against live sources (HoneyBook pricing page, Aisle Planner website, etc.)
2. If prices differ, update the table or remove pricing row entirely
3. Add a timestamp footnote to pricing row: "Pricing checked April 6, 2026. Prices may change without notice."
4. Consider automating price updates via API, or schedule a quarterly price verification audit.

Medium-Priority Issues

"Adjacent" Feature Claims Need Sourcing
Issue: The comparison table marks many competitor features as "adjacent" (~), which means "related capability exists but not a 1:1 match". This is defensible but relies on subjective judgment. If a competitor disputes this, the page should have footnotes linking to the evidence sources.
Examples (features/page.tsx lines 33-45) { feature: 'Guest Management & RSVPs', you: true, honeybook: 'adjacent', ... } { feature: 'Client Portal / Couple Portal', you: true, honeybook: 'adjacent', ... } { feature: 'SMS & Email Reminders', you: true, honeybook: 'adjacent', ... }
Recommendation Good news: The compare/data.ts file (lines 31-134) includes detailed sourcing for each row, explaining why each is marked as true/'adjacent'/false. This is comprehensive audit work.
Next step: Link from the comparison table to the source-backed compare pages (/compare/honeybook, /compare/aisle-planner) so users can see the evidence behind each claim. The page already does this at line 190: "For source-backed detail on each row, see the full comparison pages." Good!

Recommendations & Next Steps

High Priority: Complete Before Next Marketing Push

1. Add Disclaimers to Metrics
Add visible footnotes or qualifiers to "99.9% Uptime" and "48k+ Guests" metrics to avoid regulatory risk or credibility challenges. Options:
Option A (Quick): Add a small footnote below metrics:
"Metrics reflect aggregated data from professional planners using The Special Wedding. Uptime SLA terms apply—see link. Guests managed from Jan 2024–present."

Option B (Better): Modify metric labels to include qualifier:
• "48k+ Guests (managed by planners)"
• "99.9% Uptime*" → footnote links to SLA
2. Verify & Update Competitor Pricing
Before the next product release, audit competitor pricing against live sources. If HoneyBook is now $32.50/mo, update the comparison table or consider removing pricing row entirely (it changes frequently and creates maintenance burden).
Steps:
1. Check HoneyBook official pricing page
2. Check Aisle Planner official pricing page
3. Check Planning Pod official pricing page
4. Update features/page.tsx lines 181-184 if any prices changed
5. Consider adding a "Prices verified: April 6, 2026" footnote specifically to the pricing row
3. Fix CTA Redundancy in Hero Section
The homepage hero shows "Start your free trial" twice in quick succession (lines 423 and 427). One is a live button and one is a fallback for clones. Remove the redundancy.
Suggested Fix:
Either (1) use a different CTA text for the fallback (e.g., "Try free now"), or (2) consolidate both buttons into a single component that handles both active and clone states. Currently the code duplication is minimal, but the visual redundancy hurts CTA clarity.

Medium Priority: Track for Future Audits

1. Schedule Quarterly Competitor Audit
The audit notes reference "sources reviewed on April 6, 2026". As competitors add features and change pricing, this data will age. Recommend scheduling a quarterly audit to refresh comparison table accuracy.
2. Monitor "Adjacent" Feature Claims
The comparison table marks many rows as "adjacent" (not exact matches). While this is defensible and well-sourced, be prepared to defend each claim if a competitor challenges the comparison. Keep the source documentation (compare/data.ts) up to date.
3. Testimonial Verification Process
Current fallback testimonials are strong and attributed. If you fetch testimonials from an admin CMS, ensure a verification workflow is in place (real names, companies, optionally verified contact or permission to publish).

Low Priority: Nice-to-Have Improvements

1. Vary CTA Language Slightly More
While CTA variation has improved, consider A/B testing even more variation:
• Hero: "Start your free trial"
• Pricing: "Try [Plan] free"
• Bottom: "Get started free"
• Features bottom: "See all features free" or "Explore 18 tools free"

This helps reduce "banner blindness" and makes each section feel fresh.
2. Consider Case Studies Beyond Testimonials
The testimonials are strong, but adding a dedicated case study (e.g., "How Día Perfecto Weddings scaled from 8 to 15 weddings/month") could deepen credibility.
3. Hero Copy Emphasis Experiment
Current hero subhead reads: "AI contracts, the Couple Portal, and SMS reminders lead the way, with guest management, budgets, seating, vendor CRM, and day-of execution woven into one elegant workspace."

Consider testing an even punchier version:
"AI contracts. Couple portal. SMS reminders. Plus 15 other tools—all in one workspace designed for professional planners who demand elegance."
